2. 個人情報領域の失敗

2-1. 学校からの名簿の無断受領

PTAが最も頻繁に違反している類型です。学校とPTAは法律上別組織のため、 学校が保有する児童・保護者の個人情報をPTAに提供する場合、保護者本人の同意が必要です。

📰 実名報道事例 静岡市は2025年に、市立小中学校20校で約9,200人分の児童生徒の個人情報が、 保護者の同意なくPTA役員に提供されていたと公表しました。利用目的は役員選出・登下校の旗振り当番等。 愛知県春日井市も2026年2月に、市立小中学校のPTAへの個人情報の不適切な取扱いについて、 全校調査の結果を公表しています。

出典: 静岡市公式資料「静岡市立小中学校における個人情報の不適切な取扱いについて」 （city.shizuoka.lg.jp/documents/58413/20260417006.pdf）／ Security NEXT「複数小中学校で同意なく個人情報をPTAへ提供 - 春日井市」（security-next.com/181502）。

事実: 上記2市では市公式資料・教育委員会発表として実名で公表。｜ 推測: 同種事例は全国で発生しており、表面化したのは氷山の一角と考えられます。 根拠は、静岡市の事例も2024年5月に教育委員会が「PTA運営の手引き」で注意喚起した後に発覚した点、 春日井市の事例も保護者からの相談がきっかけで全校調査により発覚した点で、 通報がなければ表面化しない構造が共通しているためです。

失敗の構造

  • 「学校とPTAは一体」という前提が役員・教員双方にある
  • 「役員選出のため」という大義名分が法令判断を上書きしている
  • 同意取得の手間（年度初めの様式整備）を回避する力学が働く
  • 引き継ぎで「去年もそうしていた」が判断停止の根拠になっている

再発防止の設計

入会時の個人情報取扱同意書を全会員から取得する運用に切り替え、学校から名簿を引き継ぐルートを断つ。 詳細な同意文例はセキュリティガイド第5章に掲載しています。 切替期は、入会時の様式に同意書を組み込む年度（4月）が最適です。

2-2. Google Driveの共有設定ミス

PTA固有ではなく学校管理職にも頻発するパターンですが、PTAでは特に発生確率が高くなります。

📰 実名報道事例 奈良市教育委員会は2025年7月、市立中学校においてGoogleドライブの共有設定ミスにより、 生徒211人の名前・学級、教職員27人の名前、PTAの意見等を含む議決資料が、 奈良県内の他校教職員等に閲覧可能な状態になっていたと発表しました。

出典: rocket-boys.co.jp「奈良市立中学校でファイル共有設定ミス-PTA議決資料が生徒・教員情報含み流出」、 gate02.ne.jp/lab/incident-news/nara-city-20250722/。

失敗の構造

  • 「リンクを知っている全員」設定の意味を正確に理解していない
  • 共有リンクをLINEで流す→端末を超えて拡散→検索エンジンに捕捉される、というルートが成立しうる
  • ドメイン制限機能（学校ドメイン内のみ閲覧可）の存在を知らない
  • 共有設定の年次レビューが運用に組み込まれていない

再発防止の設計

機密情報を含むフォルダは「特定のユーザーのみ」設定を必須化し、 「リンクを知っている全員」は個人情報を含まない公開資料のみに限定します。 詳細な4階層モデルはセキュリティガイド第6章を参照。 年度末（2月）に共有設定の総点検を年中行事化することが、最も実効性の高い予防策です。

2-3. 個人LINEでの名簿・写真送信

実名報道事例は性質上少なくなりますが、PTA関係者からの相談で最頻出する事例です。 一般化事例として記述します。

典型シナリオ

広報誌の校正のため、役員Aが名簿PDFを個人LINEの役員グループに投稿。 退任後も削除されず、Aがスマホを機種変更した際の旧端末を譲渡・売却した時点で、 名簿PDFが第三者の手に渡る可能性が発生する。

失敗の構造

  • 個人LINEは個人通信用であり、保管・削除責任の主体が不明確
  • 退任時にグループから抜けても、過去の投稿は退任者の端末に残る
  • 「便利だから」という現場最適化が、組織全体のリスクを引き上げる
  • LINE WORKS等の代替手段の存在を知らない、または導入コストを過大評価している

再発防止の設計

名簿・写真等の個人情報を含むファイルの個人LINEでの送信を組織ルールで明文化禁止し、 LINE WORKSの非営利特別プランへ移行します。詳細は LINE WORKS活用ガイド（準備中）。

3. 会計領域の失敗

3-1. 単独管理による横領

📰 実名報道事例 石川県金沢市の大徳中学校PTAでは、女性会計担当者がPTAの口座の通帳と印鑑を1人で管理し、 自由に預金を引き出せる立場にあったことから、約2年間にわたり会費等約1,541万円を着服したと報じられています（2024年）。 また、東京都大田区立小学校PTAでは、会計担当役員の在任期間に約600万円の使途不明金が発生したと報道されています（2024年4月）。 朝日新聞は、PTA会計の不正で約3,000万円規模の被害事例にも言及しています。

出典: TBS NEWS DIG「中学校PTA会費等1500万円 PTA会計担当者が偽造」、 読売新聞「小学校PTAで600万円の使途不明金、会計担当の行動に疑義」、 朝日新聞「横領、着服…なくならぬPTA会計の不正 約3千万円の被害も」。

失敗の構造

  • 通帳・印鑑・キャッシュカードの3点を同一人物が単独管理（最大の構造的脆弱性）
  • 「信頼している人だから」という属人的判断が、相互チェックを免除している
  • 監査が形骸化し、通帳の原本確認が省略されている
  • 会計報告が「収支のみ」で、残高推移・現金残高・通帳残高の三者照合がない
  • 長期在任（複数年連続会計担当）が、発覚機会の喪失を構造化している

再発防止の設計

通帳と印鑑を別人で管理する分離原則を導入します。具体的には、 通帳は会計担当、印鑑は会長または副会長が保管し、出金には2名の関与を必須とします。 キャッシュカードは原則発行せず、ATM出金を制度的に困難にします。 会計担当の連続在任は2年までを上限とし、年次監査は通帳原本のコピーを取得して行います。 月次の収支報告（残高推移付き）を理事会で共有し、年度末の総会では第三者監査人（OB保護者等）による 監査報告を必須化することで、属人的信頼ではなく仕組みで不正を抑止します。

3-2. 使途不明金（記録不備型）

悪意の横領ではなく、領収書管理の杜撰さ・現金取扱の不備から「説明できない支出」が積み上がる類型です。 不正と区別しにくいため、結果として担当役員が責任を問われる事態に発展します。

典型シナリオ

バザーの売上現金を会計担当が一旦自宅に持ち帰る → 数日後に銀行入金 → 入金額と売上記録に差異が発生 → 本人にも記憶が曖昧で説明できない → 監査で指摘 → 「使途不明金」として総会報告 → 不信感が長期化。

失敗の構造

  • 現金の物理的取扱いが個人裁量に委ねられている
  • 領収書の様式・保管ルールが未整備
  • 立替払いの精算プロセスが不透明（領収書を出さずに口頭で報告）
  • イベント当日の現金管理（金庫・保管場所・複数人カウント）が確立していない

再発防止の設計

現金は当日中の銀行夜間金庫投入を原則とし、自宅保管を禁止します。 立替払いは1万円超は事前申請、領収書必須、振込精算とし、現金手渡しを段階的に廃止します。 イベント当日の売上現金は2名以上で複数回カウントし、 カウント記録に両名が署名する「現金引継書」を様式化します。 会計の電子化（Google Sheetsでの収支管理）はSheets活用ガイド（準備中）を参照してください。

3-3. 「会費を会長が立て替えた」型の不透明化

会長が善意で立替払いを多用し、年度末に精算する運用は、不正の温床になりやすい類型です。 立替金額が大きくなるほど、領収書の照合が困難になります。

失敗の構造

  • 立替の上限・期限ルールがない
  • 会長個人の銀行口座とPTA口座の境界が曖昧
  • 「会長が損する形なら問題ない」という誤った前提
  • 退任時に未精算の立替金が残ると、新会長が引き継ぎを拒否しがち

再発防止の設計

立替は緊急時のみとし、原則PTA口座から直接支払う運用に切り替えます。 会計の引き継ぎ設計は、引き継ぎ設計ガイド第4章の組織カルテに、 「立替・未精算の有無」を必ず項目化してください。

4. 引き継ぎ領域の失敗

引き継ぎ失敗の構造分析は引き継ぎ設計ガイド第1章に詳細を記載しているため、 本章では具体的な失敗事例の描写と回避策に集中します。

4-1. 個人Gmail退任後のアクセス喪失

典型シナリオ

前会長が個人GmailでGoogleドライブを運用 → 退任 → 新会長就任 → 新会長が共有メールを送ろうとしたところ、過去3年分の議事録・会計データ・名簿が すべて前会長の個人Gmail内のドライブにあると判明 → 前会長に連絡 → 引退後の関与を望まず連絡頻度が低下 → オーナー権限移譲が完了せず数か月経過 → 最終的にデータの一部を諦めて再構築。

失敗の構造

  • 共通アカウント方式が未導入
  • 「Gmailは個人のもの、PTAデータは別管理」という線引きが不可能なほどファイルが混在
  • 退任前にオーナー権限移譲を行うチェックリストがない
  • 退任者の善意に依存した引き継ぎ設計

再発防止の設計

共通PTAアカウント方式への移行が唯一の根本解です。詳細手順は 引き継ぎ設計ガイド第3章。 既に個人Gmailで運用が始まっている場合の移行は、 1〜2か月かけて「新規データから共通アカウント、既存データは段階的にオーナー権限移譲」が現実的です。

4-2. 「前任者しか分からない」業者契約

典型シナリオ

広報誌印刷業者を10年以上同じ業者に発注 → 単価交渉の経緯・他業者比較の理由が文書化されていない → 新会計担当が契約更新時に「なぜこの業者なのか」を質問するが誰も答えられない → 相見積もりを取るべきか継続すべきかの判断ができないまま、慣例で更新 → 数年後、価格が市場相場より高かったと判明。

失敗の構造

  • 意思決定ログが存在しない、または更新されていない
  • 業者選定理由が「過去にトラブルがなかった」程度の認識で継承される
  • 「再検討時期」が設定されておらず、慣性で継続する
  • 長期取引による属人的関係が、組織判断を上書きしている

再発防止の設計

意思決定ログに業者選定理由・他社比較・再検討時期を必ず記載します。 再検討時期（例: 3年ごと）が来たら相見積もりを取得し、続投・変更を再判断する手順を年間スケジュールに組み込みます。 詳細テンプレートは引き継ぎ設計ガイド第4章。

4-3. 「丁寧な引き継ぎ書」が読まれずに死蔵

典型シナリオ

退任会長が3月に100ページの引き継ぎ書を作成 → 新会長は4月の繁忙期に通読する余裕がない → 分からないことは前会長に都度LINEで質問 → 引き継ぎ書は開かれないまま1年経過 → 翌年も同じ100ページを更新せず流用 → 内容が現状と乖離。

失敗の構造

  • 網羅性を追求するあまり、検索性・到達性が犠牲になっている
  • 「文書化＝引き継ぎ完了」という誤った認識
  • 更新責任者が不明確で、誰も更新しない
  • 新任が独力で読める粒度になっていない

再発防止の設計

引き継ぎは「年度末の文書化」ではなく「年間を通じた更新」に転換します。 4種の文書（組織カルテ・運用マニュアル・意思決定ログ・失敗改善ノート）を 性質ごとに分離管理する設計が、本ガイドの推奨です。詳細は 引き継ぎ設計ガイド第4章。

5. 運営文化領域の失敗

5-1. LINEグループの深夜投稿・既読圧力

PTA関係者からの相談で最頻出する不満類型です。役員の心理的負担に直結し、翌年度の引き受け手不足の主要因にもなります。

典型シナリオ

20名規模の委員会LINEグループで、夜22時に「自己紹介をお願いします」の投稿 → 既読が増えるにつれて返信プレッシャーが上昇 → 翌朝までに返信できなかった委員に 「返事まだですか」のメッセージが個別送信 → 数名が次年度の役員引き受けを拒否。

失敗の構造

  • 投稿時間・期限のルールが未設定
  • 「個人LINE」が業務連絡を兼ねており、生活時間との境界が消失
  • 既読機能が、返信を強制する社会的圧力として機能
  • 役員間の関係性が「業務」ではなく「人間関係」として構築されてしまう

再発防止の設計

第一に、業務連絡をLINE WORKS等の業務用ツールに分離し、個人LINEから業務を切り離します。 第二に、投稿時間ルール（例: 21時〜翌7時は投稿禁止）と返信期限（例: 24時間以内、翌平日中等）を 委員会発足時に明文化します。 第三に、即時返信を要する事項と非同期で良い事項を分け、後者は投稿時に「返信不要・確認のみ」と明記します。 第四に、会長・委員長は意図的に深夜・早朝の投稿を避け、文化を率先して形成します。

5-2. 「LINEやってない問題」と排除構造

典型シナリオ

委員長がLINEグループを作ろうとする → 1名が「LINEはやっていません」と表明 → 対応として「メールで個別連絡」を約束するが、グループ内の議論経過がメール側に共有されず情報格差が発生 → やがて当該委員が議論に参加しにくくなり、形式的な参加に留まる → 「あの人はやる気がない」という評価が周囲で形成される。

失敗の構造

  • 連絡手段の単一化が、特定ツール非利用者を構造的に排除
  • 情報格差の発生メカニズムへの認識不足
  • 「みんな使っているから」という多数派論理
  • 代替手段（メール・電話・紙）が形だけになっている

再発防止の設計

重要な決定事項・連絡事項はメール（または書面）を一次媒体とし、LINEグループは補助的な即時連絡に位置付けます。 LINEで議論した内容は、結論を必ずメールに転記して全員に再共有する運用ルールを定めます。 LINE WORKSはメール・カレンダー・トーク・掲示板を統合できるため、ツール選定段階での解消も検討してください。

5-3. 振り返り会議の犯人探し化

引き継ぎ設計ガイド第8章でも触れましたが、本章では具体的描写を加えます。

典型シナリオ

秋祭り後の振り返り会議で、受付の遅延が議題に → 「誰が遅刻したか」「なぜ準備が遅れたか」の追及が始まる → 特定役員Aが矢面に立たされる → Aは翌年の役員辞退を表明 → 会議後、参加者は「次回は失敗を報告しない方が安全」と学習 → 翌年度から「特に問題なし」報告が続き、同じ失敗が再発。

失敗の構造

  • 「事象 vs 個人」の議論軸の混同
  • 会長・委員長が議論をリードできていない
  • 「失敗を報告した人を称賛する」文化が未形成
  • 事実確認と責任追及を同じ場で行ってしまう

再発防止の設計

振り返り会議の冒頭で、会長自身が今期の自分の失敗を最初に共有する規範を確立します。 記録は役職名（「受付担当」）で行い、個人名を残さないルールを明文化。 議論軸を「仕組みのどこが弱かったか」に固定し、ファシリテーターが「誰が悪いか」の発言を都度言い換える役割を担います。 詳細な5項目の振り返りフレームは引き継ぎ設計ガイド第8章を参照。

5-4. 「無理してでもやる」役員の英雄化

典型シナリオ

広報担当Aが、印刷業者との交渉から原稿執筆・配布まで実質1人で担当 → 周囲が「Aさんは凄い」と称賛 → Aの作業手順は属人化し、文書化されない → Aの退任時、後任は同じ業務量を担えず、広報誌の発行頻度を半減 → 保護者から「PTAの活動が後退した」との不満。

失敗の構造

  • 個人の能力を「組織の能力」として誤認
  • 業務量の偏りを「美談」として正当化
  • 仕組み化のインセンティブが消失
  • 後任が「自分には無理」と引き受けを忌避

再発防止の設計

過剰な負担を担う役員が出現した時点で、業務量の見える化（タスクの工数記録）を行い、 分担再設計または業務削減を即座に検討します。 「素晴らしい献身」を称賛するより、「次年度の人が同じ熱量を出さなくても回る仕組み」を設計することの価値を、 会長が繰り返し言語化する必要があります。

6. デジタル運用領域の失敗

6-1. 生成AI出力の無検証発出

典型シナリオ

広報担当がChatGPTで運動会のお知らせ文を生成 → 内容を読まずに広報誌に転載 → 配布後、保護者から「記載されている雨天連絡時刻が、慣例と1時間ずれている」と指摘 → AIが過去パターンを推測で生成していたと判明 → 訂正版を再配布する事態に。

失敗の構造

  • AI出力を「下書き」ではなく「完成品」として扱う運用
  • 固有名詞・数字・日付の一次情報照合プロセスが未確立
  • 「AIが書いた」を発出時の言い訳にできるという誤認
  • 担当役員の最終確認責任の不明確化

再発防止の設計

AI出力の発出前チェックリストを作成し、固有名詞・数字・日付・法令引用の4項目を 一次情報で照合してから発出するプロセスを定型化します。 詳細運用はChatGPT活用ガイド第7章を参照してください。

6-2. 機密情報のAIへの貼付

典型シナリオ

会計担当が、保護者からの入金状況確認のため名簿PDFをChatGPTに貼り付け、 「五十音順に並べ替えて」と指示 → AIサーバに名簿が送信され、無料版のため学習データに利用可能な状態に → 後日、別件で個人情報の取扱いに関する保護者からの問い合わせがあり、本件が発覚。

失敗の構造

  • 無料版ChatGPTの学習データ利用に関する認識不足
  • 「便利だから」という現場最適化が、組織のリスク方針を上書き
  • 個人情報の伏字化スキルの不足
  • 業務効率化と個人情報保護のトレードオフの判断基準が未整備

再発防止の設計

生成AIに個人情報を入力しないルールを明文化し、固有名詞は[A][B]等への伏字化を必須とします。 要配慮個人情報（アレルギー等）は伏字化しても入力禁止とします。 詳細手順はChatGPT活用ガイド第5章。

6-3. ツール乱立による混乱

典型シナリオ

会長就任後、会長Aは新しいツールを次々導入 → Slack、Notion、Trello、Google、LINE WORKSが並走 → どの情報がどこにあるか役員間で認識が分散 → 情報の重複と欠損が同時発生 → 新任役員は「PTAは何を使っているのか」がそもそも不明 → 結局、誰もが慣れている個人LINEに回帰し、新ツール群が休眠。

失敗の構造

  • 「最新ツール導入＝デジタル化」という誤った認識
  • ツール選定の判断基準（無料・引き継ぎ可能・規約適合）が未整備
  • 既存ツールの統合・廃止プロセスがなく、追加のみが続く
  • 役員のITリテラシー分布を考慮しない一律導入

再発防止の設計

ツールは「役割ごとに1つ」を原則とし、新ツール導入時は既存ツールの廃止または統合をセットで決定します。 判断基準はセキュリティガイド第4章の6項目チェックを通過するもののみ。 導入後3か月で利用実態を測定し、休眠ツールは整理する年次レビューを設定してください。

7. 複合型の失敗（個人情報×会計×引き継ぎ）

実際に発覚する事案の多くは単一領域ではなく、複数領域の脆弱性が重なって表面化します。 複合型の典型を1つ取り上げます。

7-1. 「退任会長による持ち逃げ疑惑」シナリオ

典型シナリオ（一般化事例）

会長Aが個人Gmailで全業務を運用 → 任期終了で退任 → 新会長Bが就任 → Drive内のファイル・銀行口座・印刷業者との契約状況にBがアクセスできない → Aへの問い合わせが断続的に → 「会計が不透明」「引き継ぎを拒否している」「持ち逃げではないか」 という疑念がBから周囲に漏れる → Aの社会的評価が毀損 → 関係修復不能に → 実際にはAは悪意なく単に共通アカウント運用を知らなかっただけだったが、 関係者全員が消耗する事態に。

失敗の構造（3領域の重なり）

  • 個人情報領域: 個人Gmailに名簿等が滞留
  • 会計領域: 通帳・印鑑・口座情報の引継書が未整備
  • 引き継ぎ領域: 共通アカウント方式が未導入、退任前のアクセス移譲チェックリストなし
  • 運営文化領域: 不信が組織内で増幅する仕組み（透明性確保のプロセスが不在）

再発防止の設計

本ガイドの3つの完全版（セキュリティ・引き継ぎ設計・本ページ）を 通読し、それぞれの第6章・第3章・第1章の対策を組み合わせて実装してください。 複合型の失敗は単一の対策では防げません。 特に重要なのは、退任前の「2週間プロトコル」（引き継ぎ設計ガイド第6章）の遵守です。

8. なぜ同じ失敗が繰り返されるのか（認知バイアスの分析）

本章は失敗事例の列挙ではなく、なぜPTAという組織で同種の失敗が全国で繰り返されるのか、 その認知メカニズムを構造分析します。仕組みで対策する前に、なぜ仕組みがないのかを理解する必要があります。

8-1. 「うちは大丈夫」バイアス（正常性バイアス）

過去にトラブルが顕在化していない組織ほど、「うちのPTAは保護者も役員も善良だから問題ない」と判断しがちです。 しかし、トラブルが顕在化していない組織と、トラブルが構造的に防止されている組織は別物です。 前者は「たまたま起きていない」だけで、横領・漏えい・引き継ぎ事故のいずれもが、 今年起きるか来年起きるかの確率分布の問題に過ぎません。

8-2. 「前任者を否定したくない」バイアス（前例尊重）

新会長が前任者の運用を変更すると、「前任者を批判している」と受け取られかねないという心理的抑制が働きます。 結果、引き継いだ運用は、それが個人Gmailであろうと、単独会計管理であろうと、 「批判を避けるために継続」という意思決定になります。 これは個人の問題ではなく、組織が世代交代を許容する文化的成熟度の問題です。

8-3. 「無報酬だから」バイアス（負担正当化）

役員は無報酬で活動しており、追加の作業（同意書取得・引き継ぎ文書作成・会計分離管理）を 「これ以上の負担を強いるのは申し訳ない」という心理が、必要な対策を阻害します。 しかし、対策を講じない結果として発生する事故対応コスト（個人情報保護委員会への報告、 本人通知文書作成、関係者対応）の方が、予防コストより遥かに大きくなります。 予防は短期負担増・長期負担減、無対策は短期負担減・長期負担増の関係にあります。

8-4. 「失敗を語れない」バイアス（沈黙のスパイラル）

PTAの失敗は語られにくい性質を持ちます。理由は、 (a) 関係者が地域コミュニティで継続的に関係を持つ、(b) 子どもが在籍中である、(c) 学校との関係に波及する、 の3点です。結果、失敗は表面化せず、記録されず、後任に継承されません。 全国のPTAで同じ失敗が繰り返される構造的原因はここにあります。

8-5. 対策の処方箋

上記4バイアスの存在自体を、年度初めに役員全員で共有することが第一歩です。 「失敗を事前に予期する」「前任者批判ではなく仕組み更新と位置づける」 「予防コストの方が安い」「失敗を匿名化して記録する」 という認知の枠組みを、組織内で繰り返し言語化する必要があります。

9. 失敗を組織資産化する仕組み

失敗を個人の記憶ではなく組織の資産にするには、記録・共有・活用の3段階が必要です。

9-1. 記録: 24時間ルール

失敗・ヒヤリハットは事象発生から24時間以内に記録します。 1週間後には記憶が美化・改変されます。スマホのNotionアプリ等で音声入力でも構いません。 記録形式は以下を推奨します。

発生日: YYYY-MM-DD 事象: （何が起きたか、客観的事実のみ） 原因: （仕組みのどこが弱かったか、個人名は記載しない） 対策: （短期的な火消し） 再発防止: （仕組みとしての変更） 担当: （役職名で記述） 関連リンク: （議事録・規程改定箇所等）

9-2. 共有: 振り返り会議の必須5項目

各イベント後・四半期末・年度末に振り返り会議を開催し、 事前想定とのギャップ、ヒヤリハット、後悔、負担の偏り、次年度への申し送り、の5項目を必ず議論します。 詳細は引き継ぎ設計ガイド第8章。

9-3. 活用: 新任就任時の通読義務化

過去の失敗・改善ノートを、新任役員の就任時必読資料に位置付けます。 引き継ぎ設計ガイド第6章「4月の2週間プロトコル」のDay 4〜7（データ確認）に、 「前年度の失敗・改善ノートを通読」を明記しています。

9-4. 心理的安全性の維持

失敗の記録は、犯人探しの場になった瞬間に崩壊します。以下のルールを明文化してください。

  • 事象は記録するが、個人名は記載しない（役職名で記述）
  • 「誰が悪いか」ではなく「仕組みのどこが弱かったか」を記述
  • 失敗を報告した人を称賛する
  • 振り返り会議の冒頭で会長が自身の失敗を最初に共有する

10. 本ガイドの要点

  1. 失敗の10類型を自組織でチェックし、3つ以上該当する領域から優先対応する
  2. 個人情報領域では、学校からの名簿無断受領とDrive共有設定ミスが最頻発
  3. 会計領域では、通帳・印鑑の単独管理が最大の構造的脆弱性
  4. 引き継ぎ領域では、個人Gmail運用と「丁寧な引き継ぎ書」死蔵が二大失敗
  5. 運営文化領域では、振り返り会議の犯人探し化が再発防止を構造的に阻害する
  6. 同じ失敗が全国で繰り返される根本原因は、4つの認知バイアスにある
  7. 失敗を組織資産化するには、24時間ルール・振り返り5項目・新任通読の3段階が必要
